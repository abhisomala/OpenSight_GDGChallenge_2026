# OpenSight — Cleanup Audit (read-only)

**Scope:** static, read-only analysis of the git-tracked repo plus on-disk working tree.
Nothing was modified, moved, or deleted. The app was not run. This report only *recommends*;
a human decides what to remove.

**Method:** `git ls-files` for the published surface, `git check-ignore` / `git status --ignored`
for what is excluded, import-graph grep across all `*.py`, and cross-checks of `README.md`,
`SETUP.md`, `DEMO.md`, `CONTRACT.md`, `TECH_AUDIT.md`, and `mobile/README.md` for every asset.

**Headline:**
- The tracked repo is already clean of build artifacts — **Tier 1 has nothing tracked to remove.**
  All caches/venvs/build dirs exist on disk but are gitignored.
- All four credential files (`.env`, `credentials.json`, `token.json`, `tts_credentials.json`)
  are gitignored and **not tracked** — confirmed good.
- The real exposure for going public is **Tier 3**: two internal audit docs (`TECH_AUDIT.md`,
  `COST_ESTIMATE.md`) are tracked, and tracked Firebase config files embed project IDs + client
  API keys (these are *required to build* and Firebase client keys are public-by-design, but they
  should be key-restricted before release).
